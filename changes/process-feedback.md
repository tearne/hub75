# Process feedback

## 2026-05-03 — Possible "agile mode" addition to the framework

Context: long sysmon2 development session. Many changes ran with a relaxed cadence — short Intent only, no Approach or Plan, agent built as soon as the ask was clear, Conclusion written retrospectively, often capturing pivots/reverts. Worked well here.

User's observation: if "agile mode" becomes a thing in the framework, the instructions could suggest:

- Agent drafts brief Intent.
- Skips Approach.
- Does Build as soon as the ask is clear.
- Conclusion retrospectively includes the final approach.
- Change name updated to reflect the final state.
- No problem throwing changes away, though keeping a record of discarded ones may also be useful.
- User is invited to "flush" the change when they look like they're starting to move onto something else.
- Periodic reminders of agile mode, but no pressure to exit.
- Default mode remains planned changes.

Not usually suitable as a primary mode; opt-in per change. Captured for future framework-instruction work, not actioned in this session.
