# sysmon2

## Intent

Build a fresh `sysmon2` crate alongside the existing `sysmon`, redesigning the rendering pipeline from first principles. Same end-product behaviour — a waterfall-with-slowdown panel for CPU/RAM/Disk/Network — but a cleaner algorithm reached through top-down discussion: capturing the data for each resource, naming each stage of the pipeline as concepts surface, and ultimately rendering the panel in a way that may look familiar but rests on different underpinnings. The map is built incrementally alongside the work.

Cadence is deliberately agile. We move freely between discussion, planning, and small building steps without per-step approval gates or formal Conclusions every time work transitions phases.

## Conclusion

What shipped:

- **Map** at `usb-display/client/sysmon2/map.md` — eleven nodes capturing the conceptual model: sysmon2 root, Devices (CPU, RAM, Disk, Network), Metric, Display (Projection with Row Rendering, Slate, Vertical Mapping; plus Presentation), and Modes.
- **Crate skeleton** at `usb-display/client/sysmon2/` with modules for cpu, slate, projection, presentation, display, and main.
- **CPU vertical slice** working end-to-end: `/proc/stat` sampling → per-core ring buffers → splat-based vertical mapping with sub-pixel sliding and σ=0.7 Gaussian + `0.5/N^0.65` brightness compensation → 32×64 portrait canvas → 90° CW rotation → hub75-client.
- **Modes** with `-f` CLI flag: production default (1 s sampling, 5 fps render, ~20 min history at panel bottom) or fast development (50 ms sampling, 20 fps render, ~30 s history). Production runs at roughly a quarter of fast's CPU.

Notable design decisions captured in the map rather than the change doc:

- Per-metric ring buffers, all the same length — slow metrics scroll slower because each ring entry covers more wall-clock time, not because the rendering treats them differently. Time aligns at top of panel only; bottom rows reach different pasts per metric (matches `sysmon`'s feel).
- Window scheme `ceil(1.07^(r-1))` over 66 rows (64 visible + 2 edge) survives the redesign but means a different thing: it now governs each entry's slide rate per sample period rather than aggregating entries. Same numeric ring length (~1,185).
- Density encoding (binary on/off pixels, count = `max(1, round(v × W))` for v > 0) chosen over bar fill or gradient. Each metric has one colour shared across all its lit pixels.
- Splat-based rendering replaced an earlier window-aggregation + post-smoothing attempt that produced cross-panel pulses; the sub-pixel sliding makes motion continuous through window boundaries by construction.

Not yet built (intentionally deferred — out of scope for this vertical slice):

- RAM, Disk, Network sampling and rendering. The crate only renders CPU metrics today; other columns are dark. Adding them is parametric over the same pipeline (per-metric ring + colour + sample multiplier), per the map.

No version bump: `sysmon2` v0.1.0 is born with this change. The existing `sysmon` crate is untouched and still ships at v0.1.1 from the prior change.

No CHANGELOG entry: project doesn't currently maintain one.
