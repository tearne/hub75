# `dots-64x32` example crate + Linux→Windows cross-compile guide

**Mode:** Formal

## Intent

Two outcomes:

1. **A reference example crate, `dots-64x32`**, that places a random-coloured dot at a random position twice a second, keeps a rolling buffer of the last 20, and re-renders on each tick. Purpose: the most obvious possible "how do I send data to the panel" reference — minimal abstractions, panel size hardcoded at 64×32 to keep the reader's attention on the data flow. Optimised for *time-to-comprehension*. It also survives the panel being unplugged and replugged rather than exiting, so it can be left running on a desk.

2. **A self-contained guide for cross-compiling the crate from Linux to Windows 11 x64**, in the same crate's `README.md`. CDC transport specifically, since vendor-class on Windows usually requires an admin driver install that defeats cross-compiled distribution.

The crate sits at the top level alongside `sysmon/`, `usb/`, `usb-drop/`. It is its own standalone Cargo crate (not an in-tree example), so it demonstrates the realistic shape — `Cargo.toml` declaring `hub75-client` as a dependency with the right features pinned — that anyone copying it as a starter would write.

## Approach

### Layout

A single new top-level directory `dots-64x32/` with:

- `Cargo.toml` — depends on `hub75-client` via path (`../usb/client/rust`), pinned `default-features = false, features = ["panel-64x32", "transport-cdc"]`, plus `rand` 0.9.
- `src/main.rs` — the whole example, single file.
- `README.md` — what it does, flashing the firmware, running on Linux, the cross-compile guide, and the starter caveat.
- `.cargo/config.toml` — mingw-w64 linker scoped to the `x86_64-pc-windows-gnu` target only, so a host `cargo build` is untouched and `cargo build --target` works without env vars.

### Source shape

`src/main.rs` is one short file with two helpers — `make_random_dot()` and `connect_panel()` — and a single loop:

- `connect_panel()` opens the first panel via `Hub75Client::open(None)`, retrying once a second until one appears (so it doesn't die when started before the panel is plugged in).
- A `VecDeque<(x, y, [u8; 3])>` of capacity 20 holds the rolling dot list.
- Loop every 500 ms: push a new random dot, drop the oldest past capacity, paint a fresh all-black `WIDTH*HEIGHT` frame, and `send_frame_rgb`. A failed send (the unplug case) prints a message, blocks in `connect_panel()` until the panel returns, then carries on — the dot trail is preserved across the outage. `main` handles errors rather than propagating them.

The pacing is a visible `sleep`, not reliance on the transport's internal frame-rate cap, so the rate that controls the example is obvious from reading it.

### Cross-compile toolchain choice

`x86_64-pc-windows-gnu` + mingw-w64: available as a Debian/Ubuntu package, no MSVC licensing dance, and `serialport` compiles cleanly under it. The instructions reduce to one `apt` line + `rustup target add` + one `cargo build`. The single self-contained `.exe` depends only on in-box Windows 11 DLLs and is copied to the Windows host by any ordinary means (the panel is a display device and can't ferry it).

### README structure

The crate README runs: **What it does** (and which file to open) → **Flashing the panel firmware** (the CDC firmware build command for the matching 64×32 panel, plus a BOOTSEL/`picotool` pointer) → **Running on Linux** → **Cross-compiling for Windows 11 x64** → **Using this as a starter outside the workspace**.

### Workspace caveat

The crate uses a path dependency on `../usb/client/rust`, which only resolves inside this repo. The README's starter section gives the concrete git-reference replacement (`git = "https://github.com/tearne/hub75"`, Cargo finds the crate by name) for anyone copying it elsewhere. Acceptable trade-off: the path dep is what lets the example be exercised against unreleased client changes.

### Top-level README structure listing

The top-level `README.md` `## Structure` section was reformatted from a fenced ASCII tree (whose aligned descriptions wrapped and lost their columns in a narrow terminal) into a name-then-prose list — bold folder label, description on the next line, blank-line separated so it renders as distinct lines both raw and rendered — and the `dots-64x32/` entry added.

No `--serial` CLI flag and no cross-compile note in top-level `SETUP.md`: `open(None)` taking the first panel is what a reader wants, and only this crate cares about cross-compilation, so the guide stays local to its README.
